WHAT THIS RUN PROVES
--------------------
admin-002  Departments, courses and the prerequisite graph. CSW2 -> CSW1 is
           the link that makes every gap say "should have come from Computer
           Science Workshop 1"; get it wrong and gaps are attributed to the
           wrong place, which is worse than not attributing them.
           A prerequisite id that does not exist is a 400, NOT a silent drop:
           nothing downstream can tell "no prerequisite" from "one we lost".
           A duplicate course code is a 409.

admin-001  Upload stores the file, creates the Material and versions it.
           Re-uploading the same title produced v2 and archived v1 -- it is
           still listed, with status "archived", not deleted. Chunks cite a
           material by page, so deleting one would leave a student looking at
           a citation to a book that is not there.
           Archiving the real Django book took it out of retrieval
           immediately: the student's course summary went from 2 books to 1,
           while its 1,938 chunks stayed addressable. Restored afterwards.
           Upload does NOT embed inline. Embedding a 1,190-page textbook is
           minutes of CPU, and an HTTP request that takes minutes is a request
           that times out; the row is marked ingest_status "pending" and the
           response says which script to run.
           The stored filename is derived from the title, never taken from the
           client -- "../../.env" is a filename.

admin-003  Who did what, when. 26 rows across the whole system, filterable by
           action and by actor email. It is load-bearing rather than
           decorative: teacher-005 reads the reteach approval time from these
           rows, because reteach_units has no approved_at column.

ROLE       Every admin route returns 403 to a TEACHER as well as to a student.
           teacher_only admits teachers; uploading course material and
           rewriting the prerequisite graph are institutional acts.

A CONTRACT VIOLATION THIS RUN CAUGHT
------------------------------------
The audit actions came out as "sourced_content.approved"/"rejected" because
they were derived from the resulting status. The contract documents
"sourced_content.approve"/"reject". Those strings are an API surface -- an
admin filters with ?action= -- so the derived names matched nothing anybody
would type. Fixed to use the documented verbs, the two existing rows renamed,
and a test now parses the verb map out of the AST and checks it against the
documented set.
