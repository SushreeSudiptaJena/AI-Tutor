WHAT THIS RUN PROVES
--------------------
1. Contract shape exactly: {items:[{topic_id, topic, concepts:[{id, name,
   state}]}]}, state in solid|shaky|untested. No extra fields.
2. From a clean slate every concept is `untested` -- a first-class state, not a
   hole in the data. Omitting the concept would imply competence; a zero would
   imply failure.
3. The diagnostic drives it: six correct answers -> solid, two deliberate wrong
   answers -> shaky on exactly those two concepts.
4. Practice drives it too. Answering a generated item correctly moved
   "Virtual environments and package isolation" from shaky to solid, so
   recovery is visible and not just failure.
5. Course-scoped, user-scoped, and 401 without a token.
6. Nothing countable ships: no score, percent, grade, average, total, count,
   updated_at, seconds or duration appears anywhere in the body.

A PHANTOM CONCEPT THIS FEATURE EXPOSED
--------------------------------------
The first run showed a sixteenth concept, "Model fields and field types
(untested)", which is NOT in concepts.json -- it was dropped when it failed the
corpus evidence check at 0.56. seed.py upserts by natural key and never
deletes, so the row survived in the shared database.

GET /student/mastery is the first endpoint that lists EVERY concept in a
course, which is why this surfaced here and nowhere earlier: a phantom concept
is invisible until something enumerates the syllabus.

The orphan row had zero dependents (no gaps, no mastery, no practice items, no
diagnostic items) and was deleted, so the shared DB is clean and a full
reset_db.py + seed.py will not recreate it. The final count above is 15,
matching concepts.json exactly. The underlying code bug -- seed.py does not
prune removed content -- is recorded as infra-006, and a prune must refuse to
touch any concept with dependents, because deleting one takes a student's
history with it.
